## What native Bitwork could decide at the starting commit

`native_bitwork.load_native` verifies the original runtime manifest and loads
`bgr140.GovernedBitworkV14`. The vendor is retained unchanged. The native model
is not an LLM or a renamed feature encoder. It combines conditional count
experts, a Boolean program ensemble and governed lag-feature discovery.

`platform_bitwork.NativeDecisionRanker` converts a declared transformation family
to a binary action, rebuilds a native predictor from eligible public observations,
and predicts each candidate's coarse action class. With fewer than two distinct
eligible tasks and source states it returns cold effective probabilities.
The function scope is comparison versus other transformations. Native preference
cannot distinguish two candidates sharing that action. An accepted record is a
preference, not authority to certify a repair.

The initial function pipeline admitted and parsed source, built the import graph,
enumerated AST transformations and ran eligible GENESIS synthesis before any
cost-aware choice. It then used WORLD MODEL/INQUIRY localization, optional
MNEMONIC recall and the static chosen ranker to order candidates. Thus native
computation could change coarse proposal order, but could not decide to skip its
own cost or reduce the up-front synthesis and retrieval work.

## Information and verification boundaries

| Stage | Permitted information and consequence |
|---|---|
| Observe / represent | Parse admitted source and public API cases; no importing unfamiliar code on the host. RESONANCE and graph signatures summarize supplied observations. |
| WORLD MODEL / INQUIRY | Use repository structure and public diagnostic results to prioritize faults and probes. Reachability likelihoods are declared heuristics. |
| GENESIS / proposal ranking | Generate bounded candidates from public information. Original native BGR may rank declared action families. |
| Execution | Run source only through the configured Docker boundary. Job Objects alone do not supply filesystem or network containment. |
| WITNESS / final observer | Independently compare consequences against separate challenge and final contracts. Private rejection terminates the attempt; it does not supply repair-search feedback. |
| MNEMONIC / retained preference | Admit only records bound to source, action, runtime and verified receipts. Expired, conflicting, duplicate and unrepresentable evidence must not silently become support. |
| Recovery | Replay durable operations, reconcile uncertain dispatches and preserve original source. A missing result is never a pass. |

The new computation controller belongs to proposal and effort selection. It does
not receive private contracts, issue WITNESS receipts, grant memory admission,
replace the authoritative runtime, or bypass isolation. Its mathematical utility
is a testable approximation, not a theorem that deeper computation helps.
See the separately registered controller study and integration documentation for
the implemented policy and measurements.

## Preserved scientific limitations

The original eight-event public-trace result is still negative: native BGR
log loss **0.4864129774**, frequency **0.4206070942**, identical candidate order.
That trace never reached the first 24-observation lag checkpoint. Sparse context
backoff and mixture weights explain the behavior examined in the earlier
diagnosis; they are not evidence of coding improvement.

The later 32-stream study showed favorable native behavior on supplied temporal
relationships, worse stationary prediction and greater computational cost.
It consumed 154.061 wall seconds and 142.719 controller CPU seconds. Its
5,878,213-byte Python allocation peak is not process RSS. Native mean model wall
cost was 2.555812 seconds per 128-step stream, versus 0.001101 for frequency and
0.070894 for the conventional temporal learner. Those earlier measurements used
equal information and steps, not equal computation.

The old generator, replay checker, arithmetic auditor and historical evidence are
now checked against the original FRONTIER seal: 303 protected files are unchanged.
The original full v0.17 archive and v0.16-v0.14 predecessors remain missing.
Neither the new controller nor a synthetic prediction result closes those gaps.
