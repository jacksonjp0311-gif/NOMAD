## Question and scope

The primary question is whether the full NOMAD pipeline accepts more independently validated repairs than its cold, native-disabled adaptive and conventional frequency controls under the same information and budgets. A separate contrast asks whether native BGR contributes beyond the adaptive system with BGR disabled.

The executable adapter currently supports a strict, bounded arithmetic `solve(x, y)` function in an admitted Python repository, with independently supplied public, challenge and final contracts. GENESIS, repository analysis, INQUIRY, RESONANCE, WITNESS and MNEMONIC retain their existing roles. This protocol does not convert an arbitrary Python repository or upstream issue into that grammar. Unsupported authentic source must remain unsupported. A simplified wrapper or transplanted synthetic function cannot be reported as solving the original upstream bug.

Final acceptance is evidence on the supplied finite independent examples and permitted public tests. It is not a general semantic correctness proof.

## Four registered arms

| Arm | Adaptive pipeline | Native BGR | Candidate preference |
|---|---|---|---|
| A: cold | Disabled | Disabled | Stable cold order |
| B: adaptive ablation | Enabled | Disabled | Matched frequency preference plus existing adaptive components |
| C: full NOMAD | Enabled | Enabled | Original native BGR preference plus the same adaptive components |
| D: conventional control | Disabled | Disabled | Action-conditional frequency/search preference |

B and C differ in the native ranker. D is a conventional frequency baseline using the same admitted source, public information and candidate grammar. It is not a claim that the baseline is the strongest available coding system. All arms receive the same candidate inventory; changed inventories or public-information identities invalidate the comparison rather than silently changing the task.

Native action scope is explicitly `genesis-vs-ast`: action 0 is GENESIS synthesis and action 1 is a registered AST transformation. Historical relational-versus-other evidence is not imported into this scope. A cold native instance evaluates the original BGR predictor on both actions for a diagnostic receipt, but insufficient independent support still produces effective probabilities `(0.5, 0.5)` and unchanged ordering. A native call is not evidence of useful learning.

## Inputs and independence

An independent curator must supply a corpus manifest, immutable buggy source snapshots, public specifications, and commitments to private challenge/final contracts. The manifest pins task IDs, upstream repository URLs, full source revisions, upstream issue URLs, declared authorship groups, source-snapshot hashes, public-specification hashes and private-contract hashes.

The runner requires at least **2 training repositories**, **8 disjoint evaluation repositories** and **24 evaluation tasks**. Those are prerequisites of this protocol, not an available corpus. The current adapter may make that corpus infeasible; adapter coverage is an explicit blocker rather than a reason to substitute synthetic tasks.

Admission rejects duplicate task IDs, source snapshots and issue identities. Training and evaluation repository and declared authorship groups must be disjoint. Previously inspected repositories, including the historical FRONTIER sources and the public development candidates below, cannot be promoted into the unseen evaluation split. Private contracts must be outside every repository source mount. Public documents may contain only the declared goal, public examples and supported source selectors.

Source inspection is parse-only. Adapter coverage is checked before private outcomes are opened. The independent curator supplies the private hashes; preregistration does not read those expected values. Private payloads are read only by the trusted mission controller after native containment and recovery preflight passes. Search sees public information only; candidate code cannot mount the controller's evidence stores or private partitions.

Distinct repositories, source hashes and author-group declarations are operational independence checks. They do not prove that a curator told the truth, that repositories have no common ancestry, or that tasks were absent from every model's pretraining. Those facts require independent provenance review. Checksums bind bytes; they are not signatures or protection from a host administrator who can rewrite all trusted files.

## Frozen budgets and scheduling

The registered order seeds are **1801801, 1801807 and 1801811**. Each seed determines one common task order and a deterministic shuffled arm order for each task. Repeated seeds are repeated measurements, not independent task evidence.

All arms share the current bounded adapter's limits: GENESIS `max_eval=65000`, grammar `max_nodes=7`, one proposed candidate attempt, and at most two container dispatches for baseline/probe and candidate execution. GENESIS enumeration and registered AST candidate checks are separate work. The report retains their counts separately when the adapter exposes them; the GENESIS count must never be labelled total candidate evaluation cost.

The container policy exactly matches the native qualification policy: **10 seconds per execution, 128 MiB memory, 0.5 CPU, 16 PIDs, at most 3000 source files and 30,000,000 source bytes**. A PASS for another policy does not admit this experiment. There is no network or host-execution fallback.

The trusted controller has bounded source and synthesis inputs, but a controller-wide CPU/RSS hard cap is not currently enforced. This is a remaining platform limitation. Reported controller CPU is not container CPU. Wall time, controller CPU, clone overhead, candidate/dispatch counts and available supervisor resource observations are kept separately. There is no measured energy or electricity cost and no inferred GPU or cost saving.

The runner executes a common cold training stream once. Independently accepted training observations enter the existing validated mission memory store. B, C and D rebuild their preferences from that same store. Before every evaluation task, arm and seed, the runner copies the frozen training memory into a fresh store. Evaluation observations may be retained in that trial's isolated evidence, but they never train a later evaluation task. The runner does not reopen historical v0.14 traces as new observations, and it does not count the same receipt twice under another identity.

## Native prerequisites and source freeze

Before any private contract read or trial, the runner requires both trusted receipts:

1. Native Docker containment qualification PASS for the exact image and policy.
2. Independent isolated mission interruption/recovery PASS for the same image and policy.

The plan pins the receipt file hashes. The accepted schemas are `nomad.native-isolation-qualification.v18` and `nomad.platform-recovery-qualification.v18`. Receipts must explicitly bind the Docker backend, current host identity, policy hash, stable before/after runtime source hashes and their own canonical content hash. Every required native case must record PASS, including an actually observed live container before owner death and verified cleanup or recovery. The recovery receipt must bind the exact containment receipt used by the plan. Its retained mission evidence must match the complete sealed file map; missing, changed and unbound extra files are refused. Current local Docker readiness is checked again. Windows Job Object tests alone never satisfy the Docker prerequisite. A missing image, missing receipt, stale code, mismatched policy or HOLD produces a durable NOT_RUN receipt before private outcomes are opened.

Preregistration also pins the actual NOMAD Python sources, native runtime manifest, experiment runner, both native qualification harnesses and public development catalogue. A later code change invalidates that plan, and runtime source identities are checked again after the experiment. Each mission compares its actual admitted source snapshot with the frozen corpus identity before dispatch. Public and private JSON commitments are checked against the exact bounded bytes parsed. New source requires a new plan and independent evaluation-data review; an already observed holdout must not be relabelled unseen. Existing plans and result files are never overwritten.

Qualification receipts and curator claims remain trusted operator inputs. The runner verifies their bindings and prerequisites; it cannot turn an invented PASS document into evidence that a native experiment happened. Keep original independently observed logs and receipts available for review.

## Registered metrics and acceptance

The primary outcome is independent final accepted repair rate. Per-arm summaries retain trial counts, accepted repairs, terminal status counts, public passes and public passes rejected by an independent contract. The false-success rate uses public-pass trials as its explicit denominator; it is null when no public pass was observed. Repeated seed trials remain repeated measurements in these descriptive counts. Rejections, exhaustion and unavailable/unsupported tasks remain visible. A containment, integrity or execution failure aborts the comparison to HOLD and retains completed rows and mission journals. It must not be removed from the denominator to improve an apparent score.

Analysis groups repeated task/seed outcomes by upstream repository. The registered contrasts are **C>A, C>B and C>D**. Each contrast uses a one-sided exact paired sign test on per-repository acceptance-rate differences; ties are omitted from that sign test. Holm correction applies across the three contrasts at family-wise **alpha 0.05**. A claimed advantage requires all three contrasts to satisfy the registered thresholds with enough admitted repositories and no containment or integrity failure. Otherwise the result remains `NOT_ESTABLISHED` within this experiment.

This is a narrow preregistered test, not a power guarantee. The repository sample may be underpowered, and a null result remains a valid result. Secondary metrics describe search effort and cost; they do not rescue a failed primary test by post-hoc endpoint selection.

## What the earlier negative result does and does not explain

In the unchanged historical replay, native BGR's mean log loss was **0.48641297739326594**, compared with **0.42060709421822373** for frequency. Native Brier score was **0.14964615314873903**, compared with **0.12122448979591835** for frequency. Native probabilities were approximately **0.41984** and **0.34554** for the two historical action classes; frequency predicted **0.4** and **0.28571**. Those different forecasts produced the measured loss difference on the recorded outcomes.

That is a descriptive explanation, not an identified cause. The replay had only two training tasks, eight training observations, four evaluation tasks, truncated candidate pools and two coarse action classes. It did not isolate whether sample size, representation, temporal assumptions, model adaptation or another factor caused native BGR to lose. No causal diagnosis or retuning result is claimed. The prospective protocol changes the evaluation design without rewriting that negative result.

## Running the protocol

An immediate prerequisite check can record the current refusal without supplying a corpus or opening private results:

```powershell
py -3 -B scripts\experiment_qualification_v18.py run --qualification results\NATIVE_QUALIFICATION_DOCKER_POST_REVIEW_V018.json --recovery results\RECOVERY_FINAL_QUALIFICATION_V018.json --output runs\qualification\intelligence-not-run.json
```

After implementation has settled, the `protocol` subcommand freezes the design, seeds, metrics and code identity into a new document. Its status explicitly says that no corpus is registered; this document cannot be used as a runnable experiment plan.

```powershell
py -3 -B scripts\experiment_qualification_v18.py protocol --output runs\qualification\intelligence-design.json
```

For an independent curator, generate an empty schema template into a new path:

```powershell
py -3 -B scripts\experiment_qualification_v18.py template --output runs\curation\corpus-template.json
```

After genuine native prerequisites and an admissible fresh corpus exist, freeze the plan before evaluation. Replace the image variable with the reviewed, already local digest-pinned image. No command fetches dependencies or installs an execution backend.

```powershell
py -3 -B scripts\experiment_qualification_v18.py freeze --corpus .\curated\corpus.json --corpus-root .\curated --image $img --qualification .\receipts\native-containment.json --recovery .\receipts\native-recovery.json --output .\runs\registered-plan.json
py -3 -B scripts\experiment_qualification_v18.py run --plan .\runs\registered-plan.json --corpus-root .\curated --qualification .\receipts\native-containment.json --recovery .\receipts\native-recovery.json --output .\runs\prospective-result.json
```

The script does not resume ambiguous experiment dispatches automatically. Retained mission journals and the mission recovery workflow must establish their state; do not simply rerun the same private evaluation to erase an interrupted result.
