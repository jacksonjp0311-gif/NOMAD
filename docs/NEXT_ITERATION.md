# NOMAD roadmap to v0.19 RELEASE CANDIDATE

The release path remains **v0.17 Security & Recovery → v0.18 Platform → v0.19 Release Candidate → v1.0 Production**. Continue internal v0.18 iterations until its critical platform gates are met. An implemented candidate with a native-security HOLD is not a qualified release or permission to advance its claims. The earlier roadmap and research record remain preserved in baseline Git history.

## Close the v0.18 platform holds

| Gate | Required evidence | Current boundary |
|---|---|---|
| Native Windows containment | A reviewed, locally available digest-pinned Linux image; actual Docker/VM probes on this ROG; filesystem, credential, network, process, resource and cleanup results. | Docker is unavailable. Native container success has not been demonstrated. |
| Interrupted isolated mission | Matched uninterrupted/interrupted tasks; matching accepted source and decisions; authoritative disposal of ambiguous workers; no duplicate admitted observations or remote effects. | Controller contracts and trusted-host recovery are distinct from real container mission recovery. |
| Real external repair | Provenance-pinned repository and defect; frozen budget; public search tests separated from independent full validation and semantic contracts; repeatable container receipts. | The new adapter handles one operator-selected arithmetic target. Broad external repair is not established. |
| Complete lineage | Retrieve the authoritative historical release archive, verify expected bytes and preserve the intentionally omitted predecessor. | Desktop-package omission must not be relabeled source corruption or historical verification success. |
| Qualified distribution | Repeatable source/runtime packaging, clean-extraction checks, documented installation/recovery and critical gates recorded without suppressing failures. | A local artifact can document HOLDs. It must not be published as a verified platform release while critical gates remain open. |

Installing Docker/WSL2 or enabling virtualization is a separate host-configuration operation. Record the actual configuration and reviewed image identity before native qualification. No downloaded installer script, dependency fetch or unfamiliar test may silently run on the host as a substitute for isolation.

## v0.19 release-candidate work

1. **Integrate WORLD MODEL and INQUIRY through isolation.** Preserve graph, hypotheses and public-probe contracts. Replace host-import fixture execution with a bounded isolated observation adapter. Demonstrate useful localization and probe selection across multiple files with frozen budgets and no hidden-label access. Keep unsupported repositories on HOLD.

2. **Extend GENESIS without widening authority.** Add a repository/transformation contract only when execution and independent validation are defined. Distinguish public-correct proposals, WITNESS-supported behavior and independently final-validated repairs. A successful test exit alone cannot certify a patch.

3. **Qualify cross-mission MNEMONIC admission.** Establish stable source/task identities, receipt deduplication, epoch expiry, contradiction retention and replay rules. Prove copied or relabeled observations do not count as independent support. The v0.18 `learning.json` observation is not automatically promoted. Automatic cross-mission skill admission remains HOLD until these gates pass.

4. **Measure native Bitwork under matched budgets.** Freeze tasks, defect provenance, seeds, image, budgets and action schema before final evaluation. Compare actual native BGR with cold, frequency-only and shuffled-evidence controls. Keep public evidence separate from challenge/final evaluation. Report ties, failures and negative transfer, plus elapsed time, CPU, memory, process/test counts and any externally billed cost. Local resource measurements do not imply measured energy or dollar savings. Claim a native intelligence advantage only if matched results support it.

5. **Strengthen independent WITNESS.** Move broader-code verification into a separately protected verifier with authenticated attestations or independent integrity anchors. Bind observations to source, environment, policy, task and epoch. Challenge inputs must remain inaccessible to the candidate worker and unavailable to search. Keep the arithmetic interpreter's narrower guarantees explicit.

6. **Exercise durable operational recovery.** Test service restart, supervisor hard death, daemon unavailability, orphan containers, NTFS ownership, stale binaries/configuration and atomic source/evidence transitions on Windows. Separate controlled shutdown, process termination and power-loss claims. Never infer an external operation's outcome from a missing local process or receipt.

7. **Gate external integrations independently.** GitHub publication, merge, deployment and other external writes need their own scoped authorization, idempotency contract and authoritative readback. Preserve unresolved effects on HOLD. Local candidate acceptance does not authorize these actions.

8. **Finish release operations.** Verify clean installation, configuration, diagnostics, offline failure modes, upgrade/rollback, manifests and packaged extraction. Resolve visibility and publication authority before publishing. Publish only the version and capabilities actually qualified.

## Permanent regression and evidence requirements

- Keep the v0.14 Catalogue namespace false-positive rejected even when incomplete public tests pass.
- Preserve v0.14 negative external-transfer findings and v0.15 cold-search parity. Later platform work does not overwrite them.
- Retain original manifests, benchmark plans, failed runs and exact rerun provenance. A repaired defect does not erase its original receipt.
- Distinguish mock contract tests, trusted host execution, real container execution and independent final validation in every report.
- Keep the original BGR runtime callable and integrity-checked. A renamed heuristic or ceremonial import is not native Bitwork execution.
- Do not introduce a mandatory cloud model, unrelated orchestration, unnecessary minor versions or unapproved irreversible actions. Patches remain reserved for blocking defects.

## v1.0 entry criteria

v1.0 requires demonstrated native containment, reliable restart/recovery, reproducible supported-repository repairs, independent verification, trustworthy evidence retention, qualified installation/update paths and an explicit permissions model. Broad self-coding or learning claims need measured evidence beyond infrastructure correctness. Remaining HOLDs must be closed or the supported product scope explicitly narrowed before a production designation.
