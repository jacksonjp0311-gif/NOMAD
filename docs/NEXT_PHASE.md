# Next phase: absorb and communicate

NOMAD becomes the host. Measured pieces from Agent Colony are absorbed into the existing spine. The continuous loop is the body. Communication is the same interface the runners already use.

## What is absorbed from Colony

| Colony piece | How it lands in NOMAD |
|---|---|
| Twin control | Already present in continuous workflows. Treatment updates; control freezes. Scoreboard on public success. |
| Witness log | Continuous log + existing WITNESS receipts. Append-only. |
| Gate that kills keep | Existing Oracle-style checks + platform gates. FAIL ends the candidate. |
| Fitness / genomes | Prior and MNEMONIC updates biased by measured success. No free mutation. |
| Communication bus | Task → fixed readout → outcome → receipt. The same path for runners and for later human messages. |
| Human authorize ceiling | Unchanged. Durable field or skill promotion waits for external authorize. |
| Continuous runners | Awake and sleep workflows already added. |

Hive-style Bitwork retrieval and the Colony registry pattern can be absorbed next as a chooser and role layer if the twin control shows value.

## Continuous loop (current)

- Awake: load prior + MNEMONIC, run bounded GENESIS on public task, record outcome.
- Sleep: consolidate prior from successes. Control arm freezes.
- Fitness: public-example correctness. Next: predictive compression proxy (bits under the shared model).

## Communication interface

The system is reached the same way the runners reach it:

1. Task string.
2. Fixed readout from the memory field (activations + exact overlap numbers).
3. Outcome (candidate, success, abstention, receipt).
4. Optional human authorize for anything that should become durable.

No separate chat surface is required at first. The runners and the human use the same path.

## Next concrete steps

1. Wire real MNEMONIC recording on public success (still candidate until authorize).
2. Add a simple predictive compression score alongside public success.
3. Expose the continuous loop through the existing platform CLI so a human can send a task and receive the readout + outcome.
4. Absorb a minimal Colony-style registry if the twin control shows the loop is stable.
5. Keep all existing HOLDs and claim boundaries.

The host absorbs what is measured. Nothing is promoted because it was interesting.
